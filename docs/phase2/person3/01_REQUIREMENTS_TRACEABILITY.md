## How to read this matrix

- **RQ-Axx**: requirement from the official assignment (S-01) — `REQUIRED_BY_ASSIGNMENT`.
- **RQ-Pxx**: requirement from the team's Phase 1 report (S-02) — `DERIVED_FROM_PHASE1`.
- **RQ-Txx**: integration requirement that needs a `TEAM_DECISION`. No team approval exists yet; some decisions are approved provisionally by the Project Owner for isolated development (T2, 2026-11-07).
- Table A records **where each requirement comes from and who owns it**. Table B records **how it will be met and proven**. Both tables use the same IDs.
- Status values: `IMPLEMENTED (isolated …)` (the stated structure, constraint or dataset is built and verified in the isolated test database; not yet integrated; **it says nothing about a business function that uses it**), `PARTIAL (structure only)` (the tables and constraints exist, but the function the requirement asks for has no implementation and no runtime evidence), `NOT IMPLEMENTED` (no code exists), `PLANNED` (a plan exists; build not started), `BLOCKED (D-xxx)` (cannot be built until that decision is approved), `SCOPE PENDING (D-001)` (P3 ownership not yet confirmed), `TEAM` (the team, not P3, must deliver it). Since 2026-11-07 the P1 schema requirements are implemented in the isolated test database (WO-P3-P1-01); nothing is integrated into a shared database.
- Owner values: `P3` = Person 3; `TEAM` = whole group; `UC01-owner` / `UC04-owner` = whoever owns those use cases (identity unknown, S-10 MISSING).
